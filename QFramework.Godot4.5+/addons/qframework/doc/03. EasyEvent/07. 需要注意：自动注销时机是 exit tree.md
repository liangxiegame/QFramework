EasyEvent 的自动注销的时机是 exiting tree。

而节点只要换了父节点或者从父节点移除自己，就会触发 exiting tree。

而之前的例子中我们都在 ready 时机注册并关联了自动注销，这种时候只要当前脚本所在的节点触发 exit tree 时机，事件就会自动注销了，这是需要在使用自动注销时要注意的点。

笔者没有找到与 ready 时机对仗的生命周期函数，而 exit tree 是与 enter tree 对仗的。

如果遇到某个注册事件的脚本需要变换父节点，这个时候有几种注销事件的方案:

**在 enter tree 时注册事件，然后使用自动注销。但是 enter tree 是在 ready 之前会调用一次，如果要使用注册时调用一次的功能，同时还需要访问子节点，那么不太适合用 @onready 这个注解定义子节点为变量，而是使用$或者%直接获取子节点。**

参考代码如下:
``` python
extends Node

var event_a:EasyEvent = EasyEvent.new()

@onready var child_node:Node = $ChildNode # onready 是在 enter tree 之后

# 懒加载模式
var _child_node:Node = null
var child_node_lazy:Node:
	get:
		if _child_node == null:
			_child_node = $ChildNode
		return _child_node

func _enter_tree() -> void:
	event_a.register_with_a_call(func():
		# 这种可以用，
		$ChildNode.name = "123"
		# 或者用懒加载的方式
		child_node_lazy.name = "123"
		# 这种就不能用了，此时是 null
		child_node.name = "123"
		
	).un_register_when_node_exiting_tree(self)

```



**在 ready 注册事件，但是在确定销毁此节点的时机手动注销。**

参考代码如下:
``` python
extends Node

var event_a:EasyEvent = EasyEvent.new()
var event_b:EasyEvent = EasyEvent.new()

var event_a_un_register:UnRegister

func _ready() -> void:
	
	event_a_un_register = event_a.register(func():
		pass
	)
	
	event_b.register(_on_event_b)
	
func _on_event_b():
	pass

	
func _notification(what: int) -> void:
	
	# 确定此脚本要销毁了
	if what == NOTIFICATION_PREDELETE:
		
		# 通过 un_register 注销
		event_a_un_register.un_register()
		
		# 通过函数注销
		event_b.un_register(_on_event_b)
	

```

**最后一种就是，父节点会变换的脚本就不用自动注销，不会变换的就用自动注销**

笔者在开发项目时很少遇到过需要使用以上解决方案的场景，绝大多数无脑自动注销就可以了，但是有的项目会用对象池，而对象池有的时候会变换父节点，有的项目的节点会需要变换父节点，所以这里提前推测了下使用 EasyEvent 可能会遇到的问题。

在未来如果使用 EasyEvent 遇到了一些不可控的问题，可以考虑下排查下是不是 exiting tree 生命周期导致的事件被提前注销导致的问题。
