我们接着介绍第二种在销毁时自动注销的方式。

即子节点的方式在节点销毁时自动注销。

我们来看下基本使用。

## 基本使用

我们在任意场景的根节点下，创建一个 Node，名字叫 EventReceiver2 ，如下所示:

![](https://file.liangxiegame.com/bcc2ca38-0b0d-4f55-b34e-9495be281dab.png)

然后在根节点创建脚本，在脚本中定义一个静态事件，然后按空格触发事件，按 1 则销毁子节点，代码如下:

``` python
extends Node2D

class_name EasyEventUnRegisterByChildNode

# 定义
static var some_event:EasyEvent = EasyEvent.new()

# 获取子节点
@onready var event_receiver_2: Node = $EventReceiver2


func _process(_delta: float) -> void:
	
	# 按下空格键，触发事件
	if Input.is_key_pressed(KEY_SPACE):
		print("空格按下")
		some_event.trigger()
		
		
	# 按下数字 1 键，销毁子节点
	if Input.is_key_pressed(KEY_1):
		if event_receiver_2 != null:
			event_receiver_2.queue_free()
			event_receiver_2 = null

```

然后在子节点，编写脚本，注册这个静态事件即可，代码如下:

``` python
extends Node

class_name EasyEventReceiver2

func _ready() -> void:
	
	EasyEventUnRegisterByChildNode.some_event.register(func():
		print("on some event triggered")	
	).un_register_when_created_child_node_destroyed(self)

```

运行当前场景，当按下空格键后，结果如下:
![](https://file.liangxiegame.com/6f80968e-494e-4310-8818-d2d420a73937.png)

按下数字 1 键，后再按下空格，结果如下:

![](https://file.liangxiegame.com/37a249b8-9510-4258-b485-94fdb8a22f80.png)

事件自动注销成功了。


## 两种方式优劣
* 通过继承 NodeWithDestroyEvent 的方式
	* 好处是没有不可控因素，只要这个节点被销毁，肯定会自动注销
	* 坏处是需要继承 NodeWithDestroyEvent 节点，比如如果是此时的节点是 Sprite 类型，而恰好又需要用到 Sprite 相关的 API，则不太适合用这种方式。
* 通过创建一个子节点的方式
	* 好处是不用继承 NodeWithDestroyEvent 节点，可以访问当前节点类型的 API
	* 坏处是如果有一些遍历子节点的操作，新参与的节点也会参与遍历，比如有时候我们需要删除掉全部的子节点，那么很有可能会把子节点无删除，导致一些不可控的行为。

## 与 ExitingTree 相比的优势
* 好处是，更改父节点不会误触发自动注销事件
* 可控性更好
