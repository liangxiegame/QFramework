在很多时候，我们需要在特定状态里进行计时、处理用户输入等操作，所以 EasyFSM 的状态（State）除了支持 enter 和 exit 生命周期，还支持了 process 生命周期。

我们来看下基本使用。

## 基本使用

在任意场景任意节点，编写如下脚本：

``` python
extends Node2D

# 使用枚举定义状态 id
enum States
{
	Idle,
	Jump
}

# 定义 FSM
var fsm:EasyFSM = EasyFSM.new()

func _ready() -> void:
	
	# 定义 Idle 状态
	fsm.state(
		States.Idle
	).on_enter(func():
		print("idle state enter")	
	).on_process(func(_delta:float):
		# 数字 2 按下，跳转到 Jump 状态
		if Input.is_key_pressed(KEY_2):
			fsm.change_state(States.Jump)	
	).on_exit(func():
		print("idle state exit")	
	)
	
	
	# 定义 Jump 状态
	fsm.state(
		States.Jump
	).on_enter(func():
		print("jump state exit")	
	).on_process(func(_delta:float):
		# 数字 1 按下，跳转到 Idle 状态
		if Input.is_key_pressed(KEY_1):
			fsm.change_state(States.Idle)	
	).on_exit(func():
		print("jump state enter")	
	)
	
	# 设置初始状态 
	fsm.start_state(States.Idle)

func _process(delta: float) -> void:
	# 使用 process 生命周期，需要 Node 的 process 生命周期驱动
	fsm.process(delta)
	
func _exit_tree() -> void:
	fsm.clear()
	fsm = null

```

代码很简单，我们在每个状态的 on_process 里去监听特定的按键输入，而不是像上一个示例一样，统一在节点的 _process 里 去监听。

## 优势

在状态的 on_process 里处理一些逻辑与在节点的 \_process 里处理一些逻辑相比，前者的代码更清晰且容易管理，后者当状态一多就会得到一个巨大的 process 函数和大量的 if 语句。
