我们看下当前编写的计数器应用代码，如下:
``` python
extends Control

# controller
class_name CounterAppController

# view
@onready var btn_add: Button = $BtnAdd
@onready var btn_sub: Button = $BtnSub
@onready var count_label: Label = $CountLabel

# model
var count:int = 0

func _ready() -> void:
	# 监听输入
	btn_add.pressed.connect(func():
		# 交互逻辑
		count += 1
		# 表现逻辑
		_update_view()	
	)
	
	# 监听输入 
	btn_sub.pressed.connect(func():
		# 交互逻辑
		count -= 1
		# 表现逻辑
		_update_view()	
	)

func _update_view():
	count_label.text = "%d" % count
```

代码中写了一些注释，我们来简单分析一下。
首先是 MVC，即 Model、View、Controller

Model 的代码如下:

``` python
# model
var count:int = 0
```

非常简单，只有一个成员变量，但是在这里它其实并不算是一个 Model，他只是要在 View 中显示的一个数据而已，具体为什么不是 Model 我们在后边再说。

View 的代码如下:

``` python
# view
@onready var btn_add: Button = $BtnAdd
@onready var btn_sub: Button = $BtnSub
@onready var count_label: Label = $CountLabel
```

View 的代码很简单，View 在 QFramework 的 MVC 定义里就是提供关键组件的引用，比如这三个组件是在 Controller 代码里要用到的。

Controller 的代码如下:
``` python
func _ready() -> void:
	# 监听输入
	btn_add.pressed.connect(func():
		# 交互逻辑
		count += 1
		# 表现逻辑
		_update_view()	
	)
	
	# 监听输入 
	btn_sub.pressed.connect(func():
		# 交互逻辑
		count -= 1
		# 表现逻辑
		_update_view()	
	)

func _update_view():
	count_label.text = "%d" % count
```

Controller 主要是监听用户输入，然后修改 Model 的状态（数据），修改后要将变化更新到界面上（通过 _update_view())

使用图来表示如下:
![](https://file.liangxiegame.com/d150113d-304c-473e-bb08-90cb41eedd8e.png)
Controller 主要负责监听 View 的用户输入部分，比如按钮点击，或者一些操作，然后去修改 Model 的状态（数据)，状态修改之后，将数据变更更新到视图上。

图中就是，修改数据和更新视图两个职责。

这两种逻辑有具体的名字，监听用户输入，然后修改 Model 的状态这个流程叫做交互逻辑。

Model 状态发生变更后更新到 View 的逻辑叫做表现逻辑，如图所示:

![](https://file.liangxiegame.com/ddb47e75-c3db-49f0-a489-3d95094720e4.png)
好了，这一篇介绍了 5 个概念，分别是 Model、View、Controller 以及交互逻辑和表现逻辑。

Model 其实是需要展示的数据，更多时候 Model 的数据是需要共享的。
View 是视图，在 Godot 中是具体的一些节点引用。
Controller 是控制器，主要是负责交互逻辑和表现逻辑。
交互逻辑是从 View->Model 的控制流程。
表现逻辑是从 Model->View 的控制流程。
