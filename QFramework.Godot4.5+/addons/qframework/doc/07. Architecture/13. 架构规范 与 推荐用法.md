QFramework 架构提供了四个层级：
* 表现层：Controller
* 系统层：System
* 数据层：Model
* 工具层：Utility

除了四个层级，还提供了 Command、Query、EasyEvent、BindableProperty 等概念和工具。

这里有一套层级的规则，如下:
* 表现层：ViewController 层。负责接收输入和状态变化时的表现，一般情况下，Node 关联的脚本 均为表现层
	* 可以获取 System、Model、Utility（不推荐）
	* 可以发送 Command、Query
	* 可以监听 Event
* 系统层：System 层。帮助 Controller 承担一部分逻辑，在多个表现层共享的逻辑，比如计时系统、商城系统、成就系统等
	* 可以获取 System、Model、Utility
	* 可以监听 Event
	* 可以发送 Event
* 数据层：Model 层。负责数据的定义、数据的增删改查方法的提供
	* 可以获取 Utility
	* 可以发送 Event
* 工具层：Utility 层。负责提供基础设施，比如存储方法、序列化方法、网络连接方法、蓝牙方法、SDK、框架集成等。可以集成第三方库。或者封装 API。
* Command：命令，负责数据的增删改。
	* 可以获取 System、Model、Utility
	* 可以发送 Event、Command
* Query：查询、负责数据的查询
	* 可以获取 System、Model
	* 可以发送 Query


通用规则：
* Controller 更改 System、Model 的状态必须用 Command
* System、Model 状态发生变更后通知 Controller 必须用事件或 BIndablePropery
* Controller 可以获取 System、Model 一下来进行数据查询，也可以获取 Utility 不过不推荐，可以在前期用下。
* Command、Query 不能有状态
* 上层可以直接获取下层，下层不能获取上层对象
* 下层向上层通信用事件
* 上层向下层通信用方法调用（只是做查询，状态变更用 Command），Controller 的交互逻辑为特别情况，只能用 Command 通用规则是理想状态下的一套规则，但是落实的实际项目，很有可能需要对以上规则做一些修改。


如果是打算先了解或学习 QFramework 架构，那么我推荐就先按照 QFramework 默认的架构规范来做练习项目。

如果是打算马上用 QFramework 做项目，那么可以再保持原有开发习惯的基础上，一点点引入 QFramework 的概念，比如一开始用 BindableProperty 和 Architecture 来解决 Model 和数据更新的问题。

再慢慢开始用 Command 来解决交互逻辑臃肿的问题，以此类推，直到能完全掌握全部概念，最终能修改和定制 QFramework 源码。
