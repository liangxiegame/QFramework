我们通过引入了 Command 来帮助 Controller 分担了一部分的交互逻辑。

但是表现逻辑的代码目前开起来并不是很智能。

表现逻辑的代码如下:

``` python
# 监听输入
btn_add.pressed.connect(func(): 
	# 交互逻辑
	CounterApp.send_command(IncreaseCountCommand.new())
	# 表现逻辑
	_update_view()	
)

# 监听输入 
btn_sub.pressed.connect(func():
	# 交互逻辑
	CounterApp.send_command(DecreaseCountCommand.new())
	# 表现逻辑
	_update_view()	
)
```

每次调用逻辑之后，表现逻辑部分都需要手动调用一次（UpdateView 方法）。

在一个项目中，表现逻辑的调用次数，至少会和交互逻辑的调用次数一样多。因为只要修改了数据，对应地就要把数据的变化在界面上表现出来。

而这部分调用表现逻辑的代码也会很多，所以我们引入一个事件机制来解决这个问题。

这个事件机制的使用其实是和 Command 一起使用的，这里有一个简单的小模式，如下图所示：

![](https://file.liangxiegame.com/60ccd370-7c2c-4792-8435-ff5427dc5a1b.png)

即通过 Command 修改数据，当数据发生修改后发送对应的数据变更事件。

这个是简化版本的 CQRS 原则，即 Command Query Responsibility Separiation，读写分离原则。

引入这项原则会很容易实现 事件驱动、数据驱动 架构。

在 QFramework 中，用法非常简单， 我们先在 CounterAppModel 定义一个 count_changed 事件，代码如下:

``` python
class_name CounterAppModel extends AbstractModel

const NAME:String = "CounterAppModel"

func get_model_name() -> String: return NAME

var count:int = 0 

var count_changed:EasyEvent = EasyEvent.new() # +

func init():
	pass
```

然后在 IncreaseCountCommand 和 DecreaseCountCommand 中，当 count 变更后，触发这个事件，代码如下:

``` python
class_name IncreaseCountCommand extends AbstractCommand

func execute():
	var model = get_model(CounterAppModel.NAME) as CounterAppModel
	model.count += 1
	model.count_changed.trigger() # ++

```

``` python
class_name DecreaseCountCommand extends AbstractCommand

func execute():
	var model = get_model(CounterAppModel.NAME) as CounterAppModel
	model.count -= 1
	model.count_changed.trigger() # ++

```

最后，我们在 CounterAppController 中注册这个事件，代码如下:
``` python
extends Control

# controller
class_name CounterAppController

# view
@onready var btn_add: Button = $BtnAdd
@onready var btn_sub: Button = $BtnSub
@onready var count_label: Label = $CountLabel

var _model:CounterAppModel = null

func _ready() -> void:
	# 通过架构获得 model
	_model = CounterApp.get_model(CounterAppModel.NAME)
	
	# 监听输入
	btn_add.pressed.connect(func(): 
		# 交互逻辑
		CounterApp.send_command(IncreaseCountCommand.new())
	)
	
	# 监听输入 
	btn_sub.pressed.connect(func():
		# 交互逻辑
		CounterApp.send_command(DecreaseCountCommand.new())
	)
	
	# 注册 count 变更事件
	(_model.count_changed # ++
		.register_with_a_call(_update_view) # ++
		.un_register_when_created_child_node_destroyed(self)) # ++

func _update_view():
	count_label.text = "%d" % _model.count
	
func _exit_tree() -> void:
	_model = null

```

代码很简单。

引入事件机制 和 CQRS 原则后，我们的表现逻辑的代码变少了很多。

由原来的两次主动调用
``` python
# 监听输入
btn_add.pressed.connect(func(): 
	# 交互逻辑
	CounterApp.send_command(IncreaseCountCommand.new())
	# 表现逻辑
	_update_view()	
)

# 监听输入 
btn_sub.pressed.connect(func():
	# 交互逻辑
	CounterApp.send_command(DecreaseCountCommand.new())
	# 表现逻辑
	_update_view()	
)
```

变成了一次监听事件，接收事件进行调用。

``` python
# 监听输入
btn_add.pressed.connect(func(): 
	# 交互逻辑
	CounterApp.send_command(IncreaseCountCommand.new())
)

# 监听输入 
btn_sub.pressed.connect(func():
	# 交互逻辑
	CounterApp.send_command(DecreaseCountCommand.new())
)

# 注册 count 变更事件
(_model.count_changed
	.register_with_a_call(_update_view)
	.un_register_when_created_child_node_destroyed(self))
```

这样减缓了很多表现逻辑。
