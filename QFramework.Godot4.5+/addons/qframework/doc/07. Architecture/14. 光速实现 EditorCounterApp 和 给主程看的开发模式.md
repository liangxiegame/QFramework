首先，我们来做一个好玩的事情，就是在前边已经实现好的 CounterApp 的基础上，光速实现一个编辑器版本的 CounterApp。

首先我们在 addons 目录下创建搞一个 editor_counter_app 文件夹，同时创建一个  plugin.cfg  和 plugin.gd 两个文件。

plugin.cfg 代码如下:
``` ini
[plugin]

name="editor counter app"
description="counter app 编辑器版 "
author="liangxiegame"
version="v0.1.1"
script="plugin.gd"
```

plugin.gd 代码如下:
``` go
@tool
extends EditorPlugin

class_name EditorCounterPlugin

# 编辑器根节点
var root_area: VBoxContainer

# 架构
var architecture:CounterAppArchitecture;

func _enter_tree() -> void:	
	root_area = VBoxContainer.new()
	# 将架构添加到 编辑器的根节点
	architecture = CounterAppArchitecture.new()
	root_area.add_child(architecture)
	# 将编辑器添加到底部栏
	add_control_to_bottom_panel(root_area,"EditorCounterApp")

func _ready() -> void:
	# 添加按钮
	var add_button = Button.new()
	add_button.text = "+"
	add_button.pressed.connect(func():
		architecture.send_command(IncreaseCountCommand.new())	
	)
	root_area.add_child(add_button)
	
	# 计数显示
	var count_label = Label.new()
	count_label.text = "0"
	root_area.add_child(count_label)
	
	# 数值绑定
	var model = architecture.get_model(ICounterAppModel.NAME) as ICounterAppModel
	model.count.register_with_init_value(func(c:int):
		count_label.text = "%d" % c
	).un_register_when_created_child_node_destroyed(root_area)
	
	# 减少按钮
	var sub_button = Button.new()
	sub_button.text = "-"
	sub_button.pressed.connect(func():
		architecture.send_command(DecreaseCountCommand.new())	
	)
	root_area.add_child(sub_button)
		
func _exit_tree() -> void:
	# 从 dock 移除面板
	if root_area:
		remove_control_from_bottom_panel(root_area)
		root_area.free()
		root_area = null

```

因为 QFramework 写的 App ，底层三层是可以复用的。

如图所示：
![](https://file.liangxiegame.com/ee5d417a-8575-4df9-ae85-f5810b14be72.png)
底层的三层 与 表现层 的通信方式有 Command、回调/事件、方法/Query。

我们可以把表现层类比成网页前端，而底层三层类比成服务器。

那么 Command、回调/事件、方法/Query 其实就是类似于 HTTP 或者 TCP 的接口或协议。

而接口或者协议只要做好约定，那么前端就不需要关心服务端的具体实现了，而服务端也不需要关心前端的具体实现。

这就做到了在分工时，将表现层和底层三层的工作分别给不同的人来负责。

而笔者曾经做过一个这样的 Unity 项目。

在项目中笔者负责将 底层三层实现好，然后和服务器把数据和接口调好，数据的显示部分笔者用的一个快速写界面的方案，比如 xmllayout(Unity 插件，xml 写 UI) 或者 delight（Unity 插件，xml 生成 UI 代码），这种方案写界面非常快，可以用来实现系统原型。

然后等数据和接口调好，系统原型实现好后，把界面、做场景流程、做表现的工作都分配给了初学者的同事们，同事们只要看实现的系统原型，就知道调用哪些 Command/Query、监听哪些事件、或调用哪些方法，这样就可以做好分工协作了。
